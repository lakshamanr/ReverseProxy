# Redirect Proxy GUI

A WPF desktop application that provides a friendly GUI for controlling a reverse proxy. This application intercepts HTTP/HTTPS requests, merges headers, handles authentication, and redirects traffic to local development servers.

## Features

- **Start/Stop Proxy**: Control the proxy server with simple buttons
- **Rule Management**: Load, edit, and auto-reload rules from `rules.json`
- **Per-Rule Login**: Trigger hybrid token+cookie authentication for each rule
- **Live Request Logs**: View intercepted requests with original and merged headers in real-time
- **Rule Status**: See per-rule status and perform actions
- **HTTPS Support**: Intercept HTTPS traffic (requires certificate trust)

## Requirements

- **.NET 7** (or .NET 6) SDK
- **Windows** (WPF is Windows-only)
- **NuGet packages** (auto-installed):
  - Titanium.Web.Proxy
  - System.Text.Json

## Configuration

### rules.json

The `rules.json` file defines the proxy rules. Each rule specifies:

- **Match**: URL prefix to intercept (e.g., `https://api.production.com/v1/`)
- **To**: Target URL prefix to redirect to (e.g., `http://localhost:3000/v1/`)
- **ApiKey**: Optional API key to inject as `x-api-key` header
- **Headers**: Custom headers to override/add
- **Login**: Optional login configuration for authentication
- **Enabled**: Whether this rule is active

Example:

```json
[
  {
    "Match": "https://api.production.com/v1/",
    "To": "http://localhost:3000/v1/",
    "ApiKey": "my-api-key",
    "Headers": [
      { "Name": "X-Custom-From-UI", "Value": "override-value" },
      { "Name": "Cookie", "Value": "session=abc123; user_pref=dark_mode" }
    ],
    "Login": {
      "LoginUrl": "https://prod.example.com/auth/login",
      "Method": "POST",
      "ContentType": "application/json",
      "Body": "{\"username\":\"admin\",\"password\":\"pass\"}",
      "Headers": [
        { "Name": "X-Special", "Value": "1" }
      ],
      "CookiePairs": [
        { "Name": "manualSession", "Value": "manualVal" }
      ]
    },
    "Enabled": true
  }
]
```

## Usage

1. **Start the Application**: Run the application (it won't start the proxy automatically)

2. **Configure Your Browser**: Set your browser's proxy to:
   - Host: `localhost`
   - Port: `8000`
   - Protocol: HTTP/HTTPS

3. **Start the Proxy**: Click the "Start Proxy" button in the GUI

4. **Configure Rules**:
   - Edit `rules.json` directly (changes auto-reload)
   - Or use the GUI to modify selected rules and click "Save Rule"

5. **Perform Login** (optional): Select a rule and click "Perform Login" to authenticate

6. **Browse**: Navigate to URLs matching your rules in your browser

7. **View Logs**: See intercepted requests in real-time on the right panel
   - Expand "Incoming Headers" to see original request headers
   - Expand "Outgoing Headers" to see merged headers sent to target

## HTTPS Interception

To intercept HTTPS traffic, you must trust the root certificate generated by Titanium.Web.Proxy:

1. Run the application once
2. Titanium will create a root certificate in your Windows certificate store
3. Open "Certificate Manager" (certmgr.msc)
4. Navigate to "Personal" → "Certificates"
5. Find "Titanium Root Certificate Authority"
6. Export and import it to "Trusted Root Certification Authorities"

Alternatively, accept browser security warnings when they appear.

**Note**: If you don't want HTTPS interception, the proxy will still work for HTTP requests.

## How It Works

1. **Request Interception**: Titanium.Web.Proxy intercepts all requests matching your rules
2. **Header Merging**:
   - Copies all incoming headers from the browser
   - Overwrites with custom headers from `rules.json`
   - Adds API keys and authorization tokens
3. **Authentication**:
   - Performs login requests to obtain tokens/cookies
   - Stores cookies in per-rule containers
   - Injects tokens as `Authorization: Bearer` headers
4. **Request Forwarding**: Sends the modified request to the target server
5. **Response Proxying**: Returns the target's response back to the browser
6. **Logging**: Records all intercepts with full header details

## Behavioral Parity

This implementation maintains behavioral parity with the browser extension approach, including:

- Copying all production headers
- Overwriting with UI-defined headers
- Hybrid token + cookie authentication
- Per-rule login support
- Cookie persistence within session
- Auto-reload on rules.json changes

## Troubleshooting

### Proxy won't start
- Check if port 8000 is already in use
- Try running as Administrator

### No requests are being intercepted
- Verify browser proxy is set to `localhost:8000`
- Check that rules are enabled in `rules.json`
- Ensure URL prefix matches exactly (case-insensitive)

### HTTPS requests fail
- Trust the Titanium root certificate (see HTTPS Interception section)
- Or disable HTTPS interception and only proxy HTTP

### Rules not auto-reloading
- Check file permissions on `rules.json`
- Try clicking "Reload Rules" button manually
